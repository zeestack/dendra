# Release notes

What counts as breaking, and how long deprecated APIs last, is in the
[versioning policy](/versioning).

## Unreleased

From the AI/MCP security review
([#42](https://github.com/zeestack/dendra/issues/42),
[`docs/security-review-ai-mcp.md`](https://github.com/zeestack/dendra/blob/main/docs/security-review-ai-mcp.md)).

- **Unexpected errors are masked.** An error that isn't a `DendraError` used to
  reach clients and the model with its own message, which can carry SQL,
  hostnames or credentials. It now arrives as `INTERNAL: Internal error` over
  HTTP, streams, WebSockets, job snapshots, the MCP bridge and tool calls, and
  the original is logged with `console.error`. After-hooks still get the
  original. If clients relied on such a message, throw a `DendraError` instead.
- `createToolExecutor` only throws `DendraError`s, so a hand-written agent loop
  can pass the message to the model. A tool without `.ai()` answers
  `NOT_FOUND`, like a missing one, so the model can't probe for procedures.
- `createMcpToolSource` throws a remote tool's error as a new `BAD_GATEWAY` (502)
  code, with the server's text.
- `lazyToolset` throws when two tools sanitize to the same name (`a.b` and
  `a_b`), which used to route calls to the wrong one.
- **`maxBodyBytes` caps JSON bodies too.** RPC, batch and REST JSON bodies were
  read whole with no limit; now, like uploads, they're refused past the cap
  (default 10 MB) with `413 PAYLOAD_TOO_LARGE`, while reading
  ([#62](https://github.com/zeestack/dendra/issues/62)). Raise `maxBodyBytes`
  if you accept larger JSON.
- `approvals.list(ctx)` only returns actions in the caller's exact scope. When
  `scope(ctx)` returned `undefined` (say, a user with no tenant), it used to
  return every tenant's pending actions
  ([#63](https://github.com/zeestack/dendra/issues/63)).
- The example app's stdio MCP server only calls tools it listed and leaves out
  confirm tools; its agent route builds ctx from the request instead of a user
  id in the body.

## 0.12.1 — packaging fixes

Upgrade from 0.12.0 if you load dendra with `require()` or use TypeScript with
CommonJS. No API changes.

- **CommonJS shares one copy of core.** Each `require()` subpath
  (`dendra/next`, `dendra/adapter`, …) used to bundle its own copy, so
  `instanceof DendraError` failed across them, `orPage` missed core's
  `NOT_FOUND`, and `.after()` hooks reported a guard's error as `INTERNAL`.
- **CommonJS types.** TypeScript projects compiling to CommonJS got the ESM
  types for every entry; they now get `.d.cts` files. Older
  `moduleResolution: "node"` setups resolve the subpaths too.
- `dendra/package.json` is exported, and `engines` declares Node 18 or later.
- **`followJob` and `useJob`** retry as soon as the browser comes back online,
  instead of waiting out the backoff.
- The package is checked with `publint` and `are-the-types-wrong` in CI, and the
  example app is built and tested against each commit.

## 0.12.0 — API cleanup before 1.0

The first round of the 1.0 API review
([#38](https://github.com/zeestack/dendra/issues/38),
[`docs/api-review-1.0.md`](https://github.com/zeestack/dendra/blob/main/docs/api-review-1.0.md)).
Old names keep working as deprecated aliases until 0.13.

- **`dendra/adapter`** (new, experimental) holds the dispatch core:
  `resolveProc`, `invokeUnary`, `invokeStream`, and the `Proc`, `AnyProc`,
  `CallSite`, `Transport` and `ProcedureKind` types. It's for writing
  transports; apps don't need it. Importing these from `dendra` is deprecated.
- **`lazyToolSource`** replaces the context manager's `toolSource` (and
  `LazyToolSourceOptions` replaces `ToolSourceOptions`), which was easy to
  confuse with `toToolSource`.
- **Memory helpers** (`createMemoryStore`, `recallMemory`, `rememberFacts`,
  `formatMemoryBlock`) come from `dendra/memory`. Importing them from `dendra` is
  deprecated; the `MemoryStore` types stay in core.
- **Approvals:** `approve` running with the approver's ctx is now documented as
  the design. A new `proposer: (ctx) => string` option records who the model was
  acting for as `action.proposedBy`.
- **Experimental:** `runAgent`, `useAssistant`, `createContextManager`,
  `memorySource`, `lazyToolSource` and `lazyToolset` are marked experimental.
  They're outside the 1.0 guarantee and may change in a minor release.
- The low-level WebSocket functions (`attachWs`, `connectWs`, `createWsSession`,
  `createWsClient`) are documented as such: no Origin check, limits or reconnect.

**Breaking:**
- `toNextHandler` returns only `GET` and `POST`. The `PUT`, `PATCH` and `DELETE`
  it used to return could only answer 405. If you destructured them, remove them.
- `propose` is no longer on the `Approvals` object; it was internal. The tool
  executor now only accepts approvals made by `createApprovals()`.

## 0.11.0 — SSE streams and job status on the client

- **Server-Sent Events.** `createClient(url, { streamFormat: "sse" })` streams
  `.stream()` procedures as SSE instead of NDJSON, for proxies and CDNs that
  buffer NDJSON. The server picks the format from `Accept`, so no server change
  is needed. Errors still arrive as a typed `DendraClientError`, and stopping
  the loop still aborts the handler's `signal`. Idle streams send a `: ping`
  every 15 s (server option `heartbeatMs`). A `.get()` stream also works with a
  plain browser `EventSource`; close it on the `done` event.
- **Following a job in the browser.** `useJob(jobId, open)` in `dendra/react`,
  and `followJob(open)` in core, follow a background job until it succeeds or
  fails, with no polling. A dropped connection reopens after a backoff and picks
  up the current state; `NOT_FOUND`, `UNAUTHORIZED` and other coded errors stop
  it and set `error`.
- **Streams through proxies.** Stream responses send `Cache-Control: no-cache`
  and `X-Accel-Buffering: no`, and `toNodeHandler` flushes after each chunk so
  Express's `compression()` doesn't hold them back. The README's new "Deploying
  streams" section covers nginx, Caddy, compression, idle timeouts and
  WebSockets behind a proxy.

**Behaviour change:** if a stream fails before it starts (for example,
`createContext` throws), the client now throws the error. Before, the loop
received the error object as an ordinary value.

No upgrade steps are needed.

## 0.10.0 — job lifecycle, schedules and router tools

- `createServerCaller` in `dendra/next` builds request context from Next.js
  headers and reuses it within a server render.
- `inspectRouter`, named middleware and typed `.meta()` make router policy
  assertions possible without reading procedure internals.

- Per-attempt `timeoutMs` deadlines and persisted `onInterrupt: "fail"` prevent
  automatic replay of interrupted work. Late results cannot overwrite terminal
  failures; handlers that ignore cancellation keep their local concurrency slot.
- `jobs.stop({ graceMs, timeoutMs })` provides bounded shutdown and reports
  unfinished work or settlement errors. No-argument `stop()` retains its
  `Promise<void>` signature and immediate cancellation, with a 30-second bound.
- `job.schedule(id, input, calendar)` and `jobs.unschedule(id)` support durable
  daily/weekly UTC schedules. Atomic occurrence insertion and cursor advancement
  prevent duplicate occurrences across workers. Missed runs coalesce into one
  catch-up, not an unbounded backlog.
- Both built-in stores support the new policies. Custom stores explicitly
  advertise capabilities; unsupported features fail clearly.

**Upgrading:** run the new Postgres `store.schema` as owner before deploying
workers. It adds columns to existing job tables, a schedules table and its
revision sequence; grant the runtime role DML and sequence USAGE. Stop 0.9
workers before enabling new policies, or use distinct queues during transition.
Choose `retries: 0, onInterrupt: "fail"` for paid work that must not replay.
Cancellation is cooperative and cannot undo external side effects.

Daily/weekly schedules are UTC only; arbitrary cron expressions and timezones
are outside this release. Existing retry defaults remain unchanged.

## 0.9.0 — real-time and long-running work

This release also carries everything planned for 0.8, which was never published
on its own. Upgrading from 0.7.x: read **Breaking** below; it's types plus one
change to chained `.input()`.

**New**

- **Background jobs** — `createJobs({ store, pubsub, context })`,
  `jobs.define(name, { input, run, key, retries, backoff, concurrency })`, and
  `route.….background(job, map?)`, which validates, runs the guards, enqueues and
  returns `{ jobId }`. Retries with backoff, one queued-or-running job per key, a
  per-name concurrency cap, leases so a crashed worker's job is retried, and
  `job.watch(jobId, { signal })` to stream status: each state once, in order,
  with a `version` that goes up on every change. Stores:
  `createInMemoryJobStore()` and `createPgJobStore(pool)`.
- **Postgres pub/sub** — `createPgPubSub(pool)` over `LISTEN/NOTIFY`: one
  listening connection per process, reconnect with backoff, one process's
  messages arrive in order, SQL triggers can publish with `pg_notify`. Messages
  must be under 8000 bytes.
- **Pluggable pub/sub** — `createPubSub(transport)` holds the shared subscription
  logic; in-memory, Redis and Postgres are transports over it, and another broker
  is one `PubSubTransport` away.
- **`attachWsServer`** — WebSocket server with safe defaults: required Origin
  allowlist, `createContext(Request)` once per connection before the socket
  opens, 1 MB messages, 1 MB unsent backlog, 100 subscriptions per connection,
  30 s heartbeat, `revalidate`, `closeWhere`, and a clean `close()` for shutdown.
- **`createWsConnection`** — a browser connection that reconnects (0.5 s doubling
  to 10 s, with jitter), retries at once when the browser comes back online,
  reports its status, stops on 4401 (signed out) until `reconnect()`, and
  resubscribes open subscriptions.
- **Typed, validated input in middleware** — `.input()` before `.use()` types and
  validates the guard's `input`.
- **Cancellation** — every call takes `{ signal }`; stream handlers get a `signal`
  that aborts when the client disconnects, cancels or unsubscribes.
- **Batching that doesn't stall** — batch results stream back as each call
  settles; the URL names the calls (`__batch?p=a,b`); `{ batch: false }` sends a
  call alone. Old clients and servers still work with new ones.
- **`dendra/next`** — `orPage(call, { signIn })` turns `NOT_FOUND` into
  `notFound()` and `UNAUTHORIZED` into a sign-in redirect in Server Components.
- `createWsSession(router, send, ctx, { maxSubscriptions })`.

**Fixed**

- Client calls are real Promises (`.catch`, `.finally`, `instanceof Promise`),
  still lazy and still iterable for streams.
- `toNodeHandler` aborted every request as soon as its body was read.
- A batch the server rejects as a whole now rejects every call in it; they used
  to resolve to `undefined`.
- Cancelling a pub/sub subscription that was never read leaked its listener (and
  its Redis subscription).

**Breaking**

- **Types only:** `createClient` and `createWsClient` results are typed as what
  survives JSON (`Jsonify<Out>`): a `Date` is typed `string`, `undefined` and
  function properties are dropped. `createCaller` keeps the handler's real types,
  now as `Caller<R>`; `Client<R>` is the over-the-wire type.
- **Chained `.input()`:** a later `.input()` now extends the earlier one instead of
  replacing it (objects only; the earlier schema wins a shared key), and both
  validate the call.

**Upgrading:** parse date strings from client results instead of casting them to
`Date`; type `createCaller` results as `Caller<R>`; check any procedure that calls
`.input()` twice. If you hand-rolled a WebSocket server or a reconnecting browser
socket, `attachWsServer` and `createWsConnection` replace them.

## 0.7.0 — files in and out, CSRF by default

**New**

- `s.file({ types, maxBytes })` — uploads inside any `s.object`; types are checked
  against the file's bytes (PNG, JPEG, GIF, WebP, PDF, ZIP) or by MIME/extension.
- `file(body, { type, filename, inline, cacheControl, etag })` — downloads; the
  client and `createCaller` return a `Blob`. `nosniff`, safe filenames, no inline
  HTML/SVG, ETag → 304.
- `urlFor(api.x.get, input)` — a GET URL for `<img src>` and download links.
- `.get()` without a path marks an RPC read.
- Server options `maxBodyBytes` (default 10 MB) and `allowFormPosts`.
- Error codes `METHOD_NOT_ALLOWED` (405), `PAYLOAD_TOO_LARGE` (413),
  `UNSUPPORTED_MEDIA_TYPE` (415).

**Fixed**

- Zod (3 and 4), Valibot and ArkType schemas now type-check as `.input()` — the
  Standard Schema issue-path type was too narrow, leaving `input` as `unknown`.
- `toNodeHandler` decoded request bodies as UTF-8, corrupting binary uploads; it
  now streams bytes untouched.
- REST and form coercion now converts `s.integer()` fields (they arrived as strings).

**Breaking (security)**

The RPC handler used to run **any** procedure from a GET (input from the query
string) and parse POST bodies as JSON whatever the `Content-Type` — so another
site could trigger a mutation with a link, an `<img>`, or a `text/plain` form.

- GET/HEAD now reach only procedures declared `.get()`; other non-POST methods
  get `405`.
- POST must be `application/json` (`415`), or a dendra multipart upload with
  `X-Dendra: 1` (`403`).

**Upgrading:** dendra's typed client needs no change. Add `.get()` to procedures
you call by GET (e.g. image URLs), and send `Content-Type: application/json` from
hand-written `fetch`/`curl` calls.

## 0.6.0 — after-hooks

- `.after(({ ctx, input, path, transport, ok, result, error, code, durationMs }) => …)`
  runs once a call settles, on every transport including AI/MCP tools — for audit
  trails and usage recording. Awaited; a throwing hook is logged, never returned.

## 0.5.0 — context manager

- `createContextManager({ budget, sources })` — memory recall and lazy tool
  loading under one token budget, via `runAgent({ context })`.

## 0.4.0 — batteries-included validators

- `s.literal/enum/union/null/nullable/integer/record`, fluent constraints, and
  `CONFLICT` / `UNPROCESSABLE` / `TOO_MANY_REQUESTS` / `NOT_IMPLEMENTED`.
