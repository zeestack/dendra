# Files in and out — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** File uploads (`s.file()`), file downloads (`file()`), and `urlFor()` as ordinary dendra procedures, with CSRF protection and response hardening that also closes two existing holes in the RPC handler.

**Architecture:** A new `src/files.ts` owns everything file-specific (the schema, byte sniffing, `FileResult`, multipart reading, the body cap, response building). Core learns two things: a read marker from `.get()`, and how to keep `FileResult`s away from transports that can't carry them and file bytes away from `.after()` hooks. The server and client get thin wiring into `files.ts`.

**Tech Stack:** TypeScript, Web `Request`/`Response`/`FormData`/`File`/`Blob`, vitest (`npx vitest run`, includes type tests), tsup.

**Spec:** `docs/superpowers/specs/2026-10-17-files-design.md`

## Global Constraints

- Core stays zero-dependency; Web-standard APIs only (Node ≥ 20).
- JSON requests and responses from the typed client stay byte-for-byte the same (the only addition is the `X-Dendra: 1` request header).
- New `ErrorCode`s: `METHOD_NOT_ALLOWED` (405), `PAYLOAD_TOO_LARGE` (413), `UNSUPPORTED_MEDIA_TYPE` (415).
- `maxBodyBytes` default **10 MB** (`10 * 1024 * 1024`); default file `Cache-Control: private, no-store`.
- Active types forced to attachment: `text/html`, `application/xhtml+xml`, `image/svg+xml`, `text/xml`, `application/xml`, and any `*/*+xml`.
- Signature table: PNG, JPEG, GIF, WebP, PDF, ZIP.
- Match the surrounding style: header comment per module explaining *why*, sparse inline comments, `DendraError` for every rejection.
- Every task ends with `npx vitest run` and `npx tsc --noEmit` green.

## Review Focus

1. **Cross-site POST with no body and no `Content-Type`** must get 415, even on a no-input procedure. Test in Task 1.
2. **A chunked multipart upload with no `Content-Length`** that goes over `maxBodyBytes` must get 413 without buffering the whole body, on both `toFetchHandler` and `toNodeHandler`. Test in Task 3.
3. **A filename with non-ASCII characters plus `"`, `\r\n`** must produce one well-formed `Content-Disposition` header (ASCII fallback plus `filename*=`). Test in Task 4.
4. **`image/svg+xml; charset=utf-8`**, with parameters and odd casing, must still count as active and be forced to attachment. Test in Task 4.
5. **A file smaller than 16 bytes, or an empty file,** must be checked without throwing. It fails cleanly when the declared type needs a signature. Test in Task 2.

### Task 1: Error codes, the `.get()` read marker, and CSRF basics

Closes the two existing holes: RPC GET reaching mutations, and POSTs accepted under any `Content-Type`.

**Files:**
- Modify: `src/errors.ts` (3 codes)
- Modify: `src/core.ts` (`get(path?)`, read brand)
- Modify: `src/caller.ts` (`Client<R>` keeps the read brand)
- Modify: `src/server.ts` (RPC: GET only for reads; POST content-type rule in RPC and REST; `allowFormPosts` option)
- Modify: `src/client.ts` (send `X-Dendra: 1` on every request, including batch)
- Test: `test/csrf.test.ts` (new), `test/types.test-d.ts`

**Interfaces:**
- Produces: `ErrorCode` gains `"METHOD_NOT_ALLOWED" | "PAYLOAD_TOO_LARGE" | "UNSUPPORTED_MEDIA_TYPE"`.
- Produces: `Builder.get(path?: string)`. With no path it sets `method: "GET"` and adds no REST route (`buildRestTable` already skips procs without `path`). It returns a builder whose procs carry the type brand `{ readonly _read: true }`. Do this with a 4th `Builder` type param `Rd extends boolean = false` that `next`, `use`, `output` and `after` all keep; `handler`/`stream` return `Proc<…> & (Rd extends true ? ReadBrand : unknown)`. Export `type ReadBrand = { readonly _read: true }` from core.
- Produces: in `Client<R>`, a read procedure maps to `((input: In) => Promise<Out>) & ReadBrand`. Task 5 uses this brand for `urlFor`.
- Produces: `ServerOptions.allowFormPosts?: boolean` (default `false`). Task 3 fills in its form-parsing behaviour.
- Produces: `function postAllowed(req: Request, opts: ServerOptions<unknown>): boolean` in `src/server.ts`. This is the single place the POST rule from the spec lives, and Task 3 calls it.

### Task 2: `s.file()` and byte sniffing

**Files:**
- Create: `src/files.ts`
- Modify: `src/schema.ts` (export `file` as `s.file`, re-exporting from `files.ts` or defining it next to the other schemas; whichever avoids a circular import)
- Test: `test/files-schema.test.ts` (new), `test/types.test-d.ts`

**Interfaces:**
- Produces: `s.file(opts?: { types?: string[]; maxBytes?: number }): FileSchema`, where `FileSchema extends Schema<File>` and has `.describe()`. The JSON Schema is `{ type: "string", format: "binary", "x-dendra-file": true, contentMediaType?: string /* when types has exactly one MIME */, maxLength?: maxBytes }`.
- Produces: `sniffType(bytes: Uint8Array): string | undefined`. It returns `"image/png" | "image/jpeg" | "image/gif" | "image/webp" | "application/pdf" | "application/zip"` or `undefined`.
- Produces: `isFileSchema(js: JSONSchema | undefined): boolean` (checks `"x-dendra-file"`), plus `fileFields(proc: AnyProc): string[]` (the top-level property names whose schema is a file). Tasks 3 and 6 use these.

- [ ] **Step 1: Write the failing tests.** Build real byte fixtures inline: `PNG = [0x89,0x50,0x4E,0x47,0x0D,0x0A,0x1A,0x0A]`, `JPEG = [0xFF,0xD8,0xFF]`, `WEBP = "RIFF"+4 bytes+"WEBP"`, `PDF = "%PDF-"`.
  - A PNG-bytes `File` named `a.png` of type `image/png` passes `s.file({ types: ["image/png","image/jpeg","image/webp"] })`, and the result is a `File`.
  - PDF bytes labelled `image/png` → issue whose message contains `"got bytes of application/pdf"`.
  - PNG bytes labelled `image/jpeg` → rejected, because the bytes must match the declared signature type.
  - `types: ["text/csv", ".csv"]`: `report.csv` sent as `application/vnd.ms-excel` passes through the extension; `report.txt` as `text/plain` fails.
  - `maxBytes: 10` with an 11-byte file → issue mentioning `10`.
  - A bare `Blob` passes and comes out as a `File` named `"blob"`.
  - A non-Blob value (a string) → issue `"expected a file"`.
  - An empty `File` labelled `image/png` → rejected cleanly, with no throw. A 3-byte `text/plain` file with `types: ["text/plain"]` passes. *(Review Focus 5)*
  - `s.object({ f: s.file() }).jsonSchema.properties.f` deep-equals `{ type: "string", format: "binary", "x-dendra-file": true }`.
  - Type test: `InferOutput<ReturnType<typeof s.file>>` is `File`.

- [ ] **Step 2: Run** `npx vitest run test/files-schema.test.ts`. Expected: FAIL (`s.file` is not a function).

- [ ] **Step 3: Implement `s.file` and `sniffType` in `src/files.ts`.** Validation is async, reading `blob.slice(0, 16).arrayBuffer()`. A declared type "has a signature" when it's one of the six `sniffType` outputs. The type rule is exactly the spec's: a signature type must match the bytes and be in `types`; otherwise the declared MIME type **or** a `.ext` matching the filename (case-insensitive) must be in `types`.

### Task 3: Multipart requests: server reading, body cap, client encoding

**Files:**
- Modify: `src/files.ts` (`readMultipartInput`, `limitedBytes`)
- Modify: `src/server.ts` (RPC and REST multipart branches; `maxBodyBytes`; `toNodeHandler` cap)
- Modify: `src/client.ts` (multipart encoding; file calls skip the batch)
- Test: `test/files-upload.test.ts` (new)

**Interfaces:**
- Consumes: `postAllowed` (Task 1), `s.file` (Task 2).
- Produces: `ServerOptions.maxBodyBytes?: number` (default `10 * 1024 * 1024`).
- Produces: `readMultipartInput(req: Request, opts: { maxBodyBytes: number; allowFormPosts: boolean }): Promise<Record<string, unknown>>`. It throws `DendraError("PAYLOAD_TOO_LARGE")` when `Content-Length` is over the cap, or as soon as the streamed count goes over (read `req.body` with a reader, count, then parse via `new Response(bytes, { headers: { "content-type": … } }).formData()`). It throws `FORBIDDEN` when there's no `x-dendra: 1` and `allowFormPosts` is off. It merges `JSON.parse($input)` with the file parts. If `$input` is absent and form posts are allowed, string parts become fields.
- Produces: in the client, `hasBlob(input): boolean` (any top-level value `instanceof Blob`) and a `FormData` body with `$input` (JSON of the non-Blob fields) plus one part per Blob key. Don't set `content-type` on these; `fetch` adds the boundary. `X-Dendra: 1` is still sent.

- [ ] **Step 1: Write the failing tests.** The router has `covers.upload` (`workspaceId: s.integer()`, `image: s.file({ types: [png, jpeg, webp], maxBytes: 8_000_000 })`) behind a `.use()` that rejects `workspaceId !== ctx.workspaceId` with `FORBIDDEN`, plus a `.after()` recorder.
  - `createClient` → `toFetchHandler` round trip: `await api.covers.upload({ workspaceId: 3, image: pngFile })` returns `{ name: "a.png", size }` from the handler.
  - The same call with `workspaceId: 4` → `DendraClientError` with code `FORBIDDEN`; the handler never ran; the after-hook saw `code: "FORBIDDEN"`.
  - A raw multipart `Request` without `x-dendra` → 403.
  - A raw multipart form post with no `$input` and `allowFormPosts: true` → string fields arrive; REST coerces `workspaceId` to a number.
  - `maxBodyBytes: 1024`, a 2 KB body with `Content-Length` → 413 `PAYLOAD_TOO_LARGE`.
  - `maxBodyBytes: 1024`, a 2 KB body sent as a `ReadableStream` with no `Content-Length` (`duplex: "half"`) → 413; the test checks the stream was not read to the end (count pulled chunks). *(Review Focus 2)*
  - `toNodeHandler` behind a real `http.createServer` on port 0, with a chunked 2 KB upload and cap 1024 → 413.
  - The REST `POST /covers` multipart round trip works.
  - With `createClient({ batch: true })`, an upload goes direct (the fake fetch sees `/rpc/covers.upload`, not `__batch`) while a JSON call made in the same tick still batches.

- [ ] **Step 2: Run** `npx vitest run test/files-upload.test.ts`. Expected: FAIL.

- [ ] **Step 3: Implement** the server branches: a multipart POST goes to `readMultipartInput`, and its result goes through the existing `invokeUnary` (validation and `.use()` included). `toNodeHandler`'s `readBody` takes the cap and stops reading with a 413 response for multipart requests over the limit, without buffering the rest.

### Task 4: `file()` output and response safety

**Files:**
- Modify: `src/files.ts` (`file`, `FileResult`, `isFileResult`, `fileResponse`, `fileMeta`, `toBlob`)
- Modify: `src/core.ts` (`CallSite.fileResults`; metadata for `.after()`)
- Modify: `src/server.ts` (send the file response for RPC and REST; RPC batch rejects)
- Modify: `src/ws.ts`, `src/tools.ts` (`fileResults: false`)
- Modify: `src/caller.ts` (`FileResult` → `Blob`; `Client<R>` maps `Out extends FileResult ? Blob : Out`)
- Modify: `src/client.ts` (a response with `x-dendra: file` → `res.blob()`)
- Modify: `src/index.ts` (export `file`, `FileResult`, `FileOptions`)
- Test: `test/files-download.test.ts` (new), `test/types.test-d.ts`

**Interfaces:**
- Produces: `file(body: Blob | ReadableStream<Uint8Array> | ArrayBuffer | Uint8Array | string, opts: FileOptions): FileResult`, where `FileOptions = { type: string; filename?: string; inline?: boolean; cacheControl?: string; etag?: string; allowUnsafeInline?: boolean; headers?: Record<string, string> }`. `FileResult` is branded (`readonly [FILE]: true`, a module-private symbol).
- Produces: `fileResponse(f: FileResult, req: Request): Response` (headers, safety, 304), `fileMeta(f): { file: { type: string; filename?: string; size?: number } }`, `toBlob(f): Promise<Blob>`.
- Produces: `CallSite.fileResults?: boolean` (default `true`). When `false` and the handler returned a `FileResult`, `invokeUnary` throws `DendraError("NOT_IMPLEMENTED", …)` **before** the after-hooks run, so they see a failure. The message is exactly `Tool '<path>' returned a file; file outputs can't be tool results` for `transport: "tool"`, and `'<path>' returned a file; file outputs aren't supported over <batch|WebSocket>` otherwise (the batch call site passes a new `CallSite.batch?: true` so the message can say which).
- Produces: `.after()` hooks get `result: fileMeta(f)` instead of the `FileResult`.

- [ ] **Step 1: Write the failing tests.**
  - `GET /rpc/covers.get?…` on a `.get()` proc returning `file(pngBytes, { type: "image/webp", filename: "cover.webp", inline: true, cacheControl: "private, max-age=300" })` → 200 with `content-type: image/webp`, `content-disposition` starting `inline; filename="cover.webp"`, `cache-control: private, max-age=300`, `x-content-type-options: nosniff`, `x-dendra: file`, and body bytes equal to the input.
  - No `cacheControl` → `private, no-store`. No `filename` → no `content-disposition` unless `inline` is false (then a bare `attachment`).
  - A filename of `"évil\"\r\nSet-Cookie: x=1.md"` → exactly one `content-disposition` header, with no CR/LF and no unescaped `"` in the `filename="…"` part, and `filename*=UTF-8''` holding the percent-encoded original. *(Review Focus 3)*
  - `type: "text/html"` with `inline: true` → `attachment`. `type: "IMAGE/SVG+XML; charset=utf-8"` with `inline: true` → `attachment`. *(Review Focus 4)* `application/atom+xml` → `attachment`. Adding `allowUnsafeInline: true` → `inline`.
  - `opts.headers` of `{ "content-type": "text/html", "x-content-type-options": "" }` doesn't override either one.
  - `etag: "abc"` → `etag: "\"abc\""`; a request with `if-none-match: "abc"` → 304 with an empty body. `if-none-match: "zzz"` → 200.
  - Client: `await api.drafts.exportMarkdown({ draftId: 9 })` is a `Blob` with text `"# hi"`; a handler error on the same proc still gives `DendraClientError`.
  - Caller: `await createCaller(router, ctx).drafts.exportMarkdown(...)` is a `Blob`.
  - After-hook: `result` deep-equals `{ file: { type: "text/markdown", filename: "draft.md", size: 4 } }` and contains no body.
  - Tool executor on an `.ai()` proc that returns `file()` → rejects with the exact tool message; its after-hook saw `ok: false`, `code: "NOT_IMPLEMENTED"`.
  - `__batch` and WS calls to a file-returning proc → a per-call `NOT_IMPLEMENTED` error; other calls in the batch still succeed.
  - Type test: `Client<R>["drafts"]["exportMarkdown"]` returns `Promise<Blob>`.

- [ ] **Step 2: Run** `npx vitest run test/files-download.test.ts`. Expected: FAIL.

- [ ] **Step 3: Implement.** The quoted `filename=` gets an ASCII fallback: drop control characters (`\x00-\x1F\x7F`), `"` and `\`, and replace non-ASCII with `_`. `filename*=UTF-8''` + `encodeURIComponent(name)`. The active-type check runs on the media type, lowercased and with parameters stripped: it's active if it's in the Global Constraints list or ends with `+xml`. ETag compare: strip quotes and `W/` from each `If-None-Match` entry; `*` matches.
