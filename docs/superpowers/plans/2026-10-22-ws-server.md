# attachWsServer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `attachWsServer(wss, router, opts)` — accept dendra WebSocket connections on one path with an Origin allowlist, a per-connection `createContext(Request)`, resource limits, heartbeats, revalidation, app-driven closes and a clean shutdown.

**Architecture:** A new `src/ws-server.ts` owns the upgrade gate and connection lifecycle and reuses `createWsSession` from `src/ws.ts` for the message protocol. `createWsSession` gains one optional argument (`maxSubscriptions`). `ws`, `node:http` and `node:stream` are matched by structural types, never imported by `src/`.

**Tech Stack:** TypeScript, Web `Request`/`Headers`/`TextEncoder`, vitest (`npx vitest run`, includes `*.test-d.ts`), tsup; `ws` + `@types/ws` as dev dependencies for tests only.

**Spec:** `docs/superpowers/specs/2026-10-22-ws-server-design.md`

## Global Constraints

- Core stays zero-dependency: nothing in `src/` imports `ws`, `node:*`.
- Defaults: `maxPayload` **1_000_000**, `heartbeatMs` **30_000** (`0` disables), `maxBufferedBytes` **1_000_000**, `maxSubscriptions` **100**, `closeGraceMs` **1_000**, `allowMissingOrigin` **false**.
- Close codes: `1001` shutdown, `1009` oversize message, `1013` backlog, `4401` revalidate `false` and `closeWhere` default (reason `"Unauthorized"`).
- Refusals: wrong/missing Origin `403`; shutting down `503`; `createContext` `DendraError` → `err.status`; other throw → `500` + `onError`. Body-less response: `HTTP/1.1 <status> <reason>\r\nConnection: close\r\nContent-Length: 0\r\n\r\n`, then `destroy()`.
- `onError` default: `console.error("[dendra] ws:", err)`.
- Existing `attachWs`, `createWsSession`, `connectWs` behave exactly as before.
- Match the surrounding style: a header comment per module explaining *why*, sparse inline comments.
- Every task ends with `npx vitest run` and `npx tsc --noEmit` green.

## Review Focus

1. **A socket error after the connection opens** (client resets the TCP connection) must go to `onError`, never crash the process — `ws` throws on an `error` event with no listener. Test in Task 3.
2. **The client disconnects while `createContext` is still awaiting** must not upgrade a destroyed socket, throw, or call `onClose`. Test in Task 2.
3. **`Origin: null`** (sandboxed iframes, `file://` pages) must be refused like any unlisted origin, not treated as "missing". Test in Task 2.
4. **A path with a query string** (`/rpc/ws?v=2`) must match; **a trailing slash** (`/rpc/ws/`) must not. Test in Task 2.
5. **`closeWhere` or a missed heartbeat during `close()`** must still run `onClose` exactly once per connection. Test in Task 5.

### Task 3: Per-connection limits and heartbeat

**Files:**
- Modify: `src/ws-server.ts`
- Test: `test/ws-server.test.ts`

**Interfaces:**
- Consumes: Task 2's harness and handle.

- [ ] **Step 1: Write the failing tests:**
  - `"throws at startup when the ws server allows bigger messages than maxPayload"` — `new WebSocketServer({ noServer: true })` (ws default 100 MiB) → `attachWsServer` throws `/maxPayload/`; with `maxPayload: 1_000_000` on both it doesn't.
  - `"closes with 1009 on a message over maxPayload"` — server `maxPayload: 1000` on both; client sends 2000 bytes; client sees close code `1009`.
  - `"checks message size itself when the server exposes no options"` — a `WsServerLike` wrapper around a real server with `options` removed, `maxPayload: 1000`; 2000 bytes of multi-byte text (`"é".repeat(1000)`, 2000 bytes) → `1009`.
  - `"closes with 1013 when the unsent backlog passes maxBufferedBytes"` — `maxBufferedBytes: 10_000`; a stream yields 50 messages of 100 KB synchronously; the client pauses its socket (`(client as any)._socket.pause()`) right after subscribing; then resume; client sees `1013`.
  - `"drops a reply whose call finishes after the socket closed"` — a unary handler awaiting a test-controlled promise; close the client, then resolve; no `onError`, no throw.
  - `"terminates a socket that stops answering pings"` — `heartbeatMs: 50`; client created with `{ autoPong: false }`; within 300 ms the client sees `close`, and `size === 0`.
  - `"keeps a socket that answers pings"` — `heartbeatMs: 50`, default client; still open after 300 ms.
  - `"reports a socket error after open instead of crashing"` — after open, `serverSocket.emit("error", new Error("boom"))` (capture the server socket via `wss.on("connection")` is not used in noServer mode, so expose it by wrapping `handleUpgrade`'s callback in the test's `WsServerLike` wrapper); `onError` receives it; the process keeps running.

- [ ] **Step 2: Run** — Expected: FAIL.

- [ ] **Step 3: Implement**:
  - Startup check: `if (wss.options?.maxPayload !== undefined && wss.options.maxPayload > maxPayload) throw new Error("[dendra] ws: the ws server allows messages up to N bytes; pass { maxPayload: M } to new WebSocketServer(...)")`.
  - When `wss.options` is absent, measure each message with `TextEncoder` (Buffers by `.byteLength`) and `close(1009, "Message Too Big")` when over.
  - `send` wrapper: skip unless `readyState === 1` (OPEN); if `bufferedAmount > maxBufferedBytes`, `close(1013, "Try Again Later")` instead of sending.
  - `socket.on("error", onError)` on every accepted socket.
  - One heartbeat `setInterval` per handle (skip when `heartbeatMs === 0`), `unref?.()`; per connection an `alive` flag set by `pong`.

- [ ] **Step 4: Run** `npx vitest run && npx tsc --noEmit`. Expected: green, three runs in a row (timing tests).

### Task 5: Shutdown

**Files:**
- Modify: `src/ws-server.ts`
- Test: `test/ws-server.test.ts`

- [ ] **Step 1: Write the failing tests:**
  - `"close() refuses new upgrades with 503"`.
  - `"close() refuses an upgrade whose createContext was still running"` — start an upgrade with a slow `createContext`, call `close()`, resolve it → `503`.
  - `"close() sends 1001 and resolves after every onClose settled"` — async `onClose` that resolves after 50 ms; `await close()` resolves only after it.
  - `"close() terminates clients that ignore the close handshake after closeGraceMs"` — `closeGraceMs: 50`; the client's underlying socket is paused so it never answers; `close()` resolves within 500 ms; `onClose` ran.
  - `"onClose runs once when closeWhere or a missed heartbeat races close()"` — call `closeWhere(() => true)` then `close()` immediately; `onClose` count equals the number of connections.
  - `"close() is idempotent"` — two calls return promises that both resolve; `onClose` not repeated.
  - `"close() stops the heartbeat and revalidate timers"` — after `close()`, `check` is not called again over 200 ms.

- [ ] **Step 2: Run** — Expected: FAIL.

- [ ] **Step 3: Implement** the spec's "Shutdown" steps 1–4; memoize the promise; the grace timer `unref?.()`; closing a socket twice is a no-op because the map entry is deleted once.
