Why another API framework?

The typed-RPC space is crowded — tRPC, ts-rest, Hono, oRPC are all good at HTTP. dendra's wedge is the part they bolt on or skip: it's AI- and MCP-native by construction. A procedure and an LLM tool are the same shape — a name, an input schema, a validated handler — so dendra treats them as one thing. Mark a procedure .ai() and it's instantly a tool for Claude over MCP and for the Anthropic/OpenAI APIs, executed with the same validation that guards your HTTP endpoints.

procedure→ typed client (pure inference, no codegen)
.input(schema)→ REST endpoint + OpenAPI
.ai()→ streaming & real-time (async generators + pub/sub)
.handler(fn)→ in-process caller (RSC, zero round-trip)
 → LLM tool & MCP server (stdio + remote HTTP)

Quickstart

Define once, serve anywhere, call with full inference. No generated files.

1 Define

import { initNexus, s, type RouterRecord } from "dendra";

const { route } = initNexus<{ userId: string | null }>();

export const appRouter = {
  add: route
    .input(s.object({ a: s.number(), b: s.number() }))
    .handler(({ input }) => input.a + input.b),
} satisfies RouterRecord;

export type AppRouter = typeof appRouter;

2 Serve — Next.js App Router

// app/rpc/[...nexus]/route.ts
import { toNextHandler } from "dendra";
import { appRouter } from "@/server/router";

export const { GET, POST } = toNextHandler(appRouter, {
  createContext: (req) => ({ userId: getSession(req) }),
});

3 Call — typed, no codegen

import { createClient } from "dendra";
import type { AppRouter } from "@/server/router";

const api = createClient<AppRouter>("");
const sum = await api.add({ a: 40, b: 2 });   // number, inferred

The AI / MCP story

Your .ai() procedures become tools for LLMs and an MCP server Claude can connect to — the same handlers, the same validation, the same auth context.

import { toToolset, createToolExecutor, mcpToolDefinitions } from "dendra";

// Tool defs for Anthropic / OpenAI from your .ai() procedures:
const tools = toToolset(appRouter, { format: "anthropic" });

// Execute a tool the model chose — validated, scoped to the user's ctx:
const execute = createToolExecutor(appRouter, ctx);
await execute("notes.create", modelProvidedArgs);  // bad args rejected

// MCP: the same procedures become tools Claude can call (stdio + HTTP).
const defs = mcpToolDefinitions(appRouter);

Middleware & auth

Run logic before a handler — auth, logging, rate-limiting — and enrich the context. One .use() runs across every transport (RPC, REST, the caller, WebSocket, and AI/MCP tools). Auth stays your app's responsibility; the framework just provides the seam.

const authed = route.use(({ ctx }) => {
  if (!ctx.token) throw new NexusError("UNAUTHORIZED", "Sign in");
  return { userId: lookup(ctx.token) };   // merged into ctx, typed downstream
});

const appRouter = {
  me:     authed.handler(({ ctx }) => ctx.userId),      // ctx.userId is typed
  delete: authed.input(…).ai({ … }).handler(…),      // the tool is auth-guarded too
};

Middlewares stack (each sees the previous one's additions) and reject by throwing. Because an AI/MCP tool runs the same path, a procedure behind .use(auth) is guarded for the model too — it inherits the user's permissions, it can't bypass them.

Class controllers (NestJS-style, no decorators)

Prefer classes for grouping and dependency injection? A controller is a class whose fields are procedures — put an instance in the router. You get NestJS structure and constructor DI without decorators, reflect-metadata, or experimentalDecorators.

export class UsersController {
  #db: Db;                                   // #private: not part of the public type
  constructor(db: Db) { this.#db = db; }     // constructor injection

  list = route.get("/users").handler(() => this.#db.users.all());
  create = route
    .post("/users")
    .input(s.object({ name: s.string() }))
    .ai({ description: "Create a user" })        // still an LLM/MCP tool
    .handler(({ input }) => this.#db.users.insert(input));
}

const appRouter = { users: new UsersController(db) };  // instance = sub-router
